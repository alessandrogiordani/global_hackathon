# MCP Tools for Agent Integration

**Summary:** The MCP server provides structured data tools. The agent (created separately on workspace) handles LLM calls.

---

## 🎯 Core Tools for Library Migration Agent

### **1. `get_library_migration_analysis`** ⭐ Main Tool

**What it does:**
- Clones source repo + library L1 + library L2 (temp, auto-cleanup)
- Parses Java code to find library method invocations
- Extracts API declarations from both library versions
- Compares L1 vs L2 to detect breaking changes
- Cross-references with source code usage
- Returns structured data with full source context

**Input:**
```python
{
    "source_repo_url": "https://github.com/mycompany/app.git",
    "library_name": "spring-boot",
    "current_version": "2.7.0",
    "target_version": "3.0.0",
    "library_repo_url": "https://github.com/spring-projects/spring-boot.git"  # Optional
}
```

**Output:**
```python
{
    "status": "success",
    "breaking_changes": [
        {
            "id": "bc_001",
            "class": "org.springframework.web.servlet.config.annotation.WebMvcConfigurer",
            "method": "addResourceHandlers",
            "change_type": "signature_changed",
            "old_signature": "void addResourceHandlers(ResourceHandlerRegistry registry)",
            "new_signature": "void addResourceHandlers(ResourceHandlerRegistry registry, ContentNegotiationManager manager)",
            "affected_locations": [
                {
                    "file": "WebConfig.java",
                    "line": 42,
                    "source_context": {
                        "target_line": "public void addResourceHandlers(...)",
                        "surrounding_context": "...",
                        "full_method": "...",
                        "class_name": "WebConfig",
                        "imports": [...]
                    }
                }
            ]
        }
    ],
    "summary": {
        "breaking_changes_count": 12,
        "affected_files": 5,
        "affected_invocations": 23
    }
}
```

**Agent uses this to:**
- Iterate through `breaking_changes`
- For each `affected_location`, build LLM prompt
- Call LLM to generate patch
- Combine patches with breaking change info

### **2. `write_migration_analysis_to_uc`**

**What it does:**
- Writes migration analysis results (breaking changes + agent-generated patches) to UC
- Calculates summary metrics (complexity, effort, auto-fixable %)

**Input:**
```python
{
    "repo_id": "repo_123",
    "library": "spring-boot",
    "from_version": "2.7.0",
    "to_version": "3.0.0",
    "breaking_changes": [...],  # From Tool 1
    "patches": [  # Generated by agent using LLM
        {
            "file": "WebConfig.java",
            "line": 42,
            "old_code": "...",
            "new_code": "...",
            "confidence": "high",
            "explanation": "...",
            "generated_by": "gpt-4"
        }
    ],
    "summary": {...}
}
```

**Output:**
```python
{
    "status": "success",
    "analysis_id": "uuid",
    "message": "Analysis written to UC"
}
```

### **3. `get_sca_findings_from_uc`** (Already exists)

**What it does:**
- Reads vulnerable repos from UC table
- Returns repos with library info and candidate versions

**Use by agent:**
- Get list of repos to analyze
- Extract library name, current version, candidate versions

---

### **4. `record_user_decision_to_uc`** (Already exists)

**What it does:**
- Records user approval/rejection of migration

**Use by agent:**
- After user reviews patches in Streamlit UI
- Record decision for audit trail

## 🔄 Agent Workflow

```
1. Agent calls: get_sca_findings_from_uc()
   → Gets list of repos

2. For each repo:
   a. Agent calls: get_library_migration_analysis()
      → Gets breaking_changes[] + source_context[]
   
   b. Agent uses LLM (separate, not in MCP):
      For each breaking_change:
        - Build prompt from breaking_change + source_context
        - Call LLM (GPT-4/Claude)
        - Get updated_code
      → Generate patches[]
   
   c. Agent calls: write_migration_analysis_to_uc()
      → Writes breaking_changes + patches to UC

3. Streamlit app reads from UC and displays results
```

## ✅ Key Points

1. **MCP tools return structured data** - No LLM calls
2. **Agent handles LLM** - Separate workspace implementation
3. **Clear separation** - MCP = data, Agent = intelligence
4. **Temporary cloning** - Auto-cleanup, no workspace pollution
5. **UC integration** - Read repos, write results
